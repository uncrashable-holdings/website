# Uncrashable Holdings — Publishing Governance
### The constitution of the constitution

This document exists to do one thing: name the four documents that govern how Uncrashable Holdings publishes knowledge, state what each one is exclusively responsible for, and freeze them as of this point so the system stops being a moving target.

**Frozen: July 2026.**

---

## The Four Documents

Each answers a different question. None of them answer each other's question. That's the whole design.

| Document | Governs | Question it answers |
|---|---|---|
| **Methodology Governance** (GS-001–GS-007, Methodology OS) | The methodology itself | *Is this true?* |
| **Site Architecture v1.0** | Where knowledge lives | *Where does it go?* |
| **Editorial Standards** | What becomes knowledge | *Does it deserve to exist publicly?* |
| **Writing Scaffolds** | How knowledge is created | *How does a specific page get made well?* |

If a future question doesn't cleanly belong to one of these four, that's a signal either a fifth document is genuinely needed, or the question is actually a sub-question of one of the four and belongs there instead. Default to the second interpretation. A fifth document should be rare.

---

## The Amendment Rule

From this point forward, none of the four documents change because a new idea sounds exciting. They change only when real use, actual drafting, actual publishing, an actual conversation with a client or a board, reveals a genuine gap the document didn't account for.

Practically, that means before amending any of the four:

1. **Name the specific instance.** Not "this might be a problem someday" but "this happened, on this page, on this date, and the document had no answer."
2. **Confirm it's not already answered elsewhere.** Check the other three documents first. What feels like a gap is sometimes just a question asked of the wrong constitution.
3. **Amend the narrowest document that owns the question.** Don't touch Site Architecture to solve an Editorial Standards problem.

This keeps the system stable while still letting it evolve with evidence instead of enthusiasm. Excitement is a terrible reason to edit a constitution. A real gap, encountered in real work, is the only good one.

## The Deferred Architecture Principle

Define future structures when doing so reduces future design pressure. Build them only after the first real instance demonstrates the structure is needed.

This distinguishes two different acts that are easy to confuse. Defining is cheap: naming a pattern in prose, so it's recognized on sight the next time it appears. Building is expensive: schemas, columns, sections, tooling, anything that has to be maintained once it exists. The Amendment Rule above governs building. This principle governs the cheaper act that comes before it, and it's allowed to move faster, because a definition sitting unused costs nothing while a structure sitting unused costs upkeep and quietly accumulates the appearance of promises not kept.

Three deliberate absences in this system are the same judgment wearing three different names, and none of them were recognized as one thing until they'd already happened independently:

- **Sovereign Legacy** — excluded entirely rather than reserved, because a placeholder for an unfinished network is worse than no mention at all.
- **Doctrine** — given a threshold and a running ledger instead of an immediate fork, because two or three statements would make a thinner section, not a stronger one.
- **Concept Registry** — sketched in words, deliberately not built, because "Appears In: Podcast, Keynote, White Paper" would be listing things that don't exist yet.

Three independent instances of identical behavior, arrived at separately, is not a hypothesis waiting on proof. It's already the evidence. That's what earns this principle its place here now rather than on the "someday" list it nearly joined.

## The Mental Model

This is not a website. It is Version 1 of the Uncrashable Encyclopedia.

The Methodology OS is the private source of truth. The website is the public edition. Editorial Standards determines what graduates from private doctrine to public knowledge, and nothing above it changes that relationship. Every document in this system exists to protect that graduation process, not to speed it up.

## Scale and the Metric That Actually Matters

Long-term target: 250 to 500 evergreen pages across Framework, Glossary, Diagnostics, Verticals, Research, and Field Notes. But page count is not the metric. It's a side effect of the real one.

**The metric: Editorial Gravity.** Defined once, canonically, in Editorial Standards §10: the degree to which a concept naturally requires references to other canonical concepts within the body of its explanation. Only in-content editorial links count. Navigation links don't; a footer or nav bar connects everything to everything and proves nothing. When important pages consistently generate real editorial gravity toward at least five other important pages, the site has stopped being a website and become a knowledge graph, which is the only kind of asset that compounds instead of just accumulating.

## Reference Library, Not Resource Center

Every competitor has a resource center. A resource center says "here's an article about succession planning." A reference library says "here's the canonical definition, every place it's used, the related standards, the relevant case studies, and the framework pages that depend on it." The difference is not tone. It's architecture. Any new section proposed for the site should be tested against this distinction before it's built: does this add an article, or does it add a node to the graph.
