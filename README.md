# Uncrashable Holdings Website

This is the source for the Uncrashable Holdings public site, the canonical reference for the Continuity Architecture methodology. It builds 25 pages and two verification scripts guard its content graph and its links.

## What is in here

- `src/content/config.ts`: the schema. This is the Page Registry as validated types. A malformed Status or Evidence Level fails the build.
- Five content collections:
  - `framework/` (8): Invisible Fragility, AOIDR, the five pillars, and Methodology.
  - `diagnostics/` (4): the Diagnostics hub, Continuity Scan, Invisible Fragility Index, Continuity Stress Test.
  - `continuity-architecture/` (1): the individually scoped engagement the diagnostics lead into.
  - `about/` (1): the practitioner's identity and credentials.
  - `verticals/` (5): the Applications hub and the Homeowner, Business Owner, Nonprofit, and Athlete pages. The public label is "Applications"; the URL and folder stay `verticals`.
- Hand-written pages: Home, Start Here (deliberately unlinked from navigation), Contact, Privacy, Disclaimer, and the 404 page.
- `src/layouts/BaseLayout.astro`: the shared shell. Head metadata, canonical and Open Graph tags, self-hosted fonts, Visual Doctrine styling, skip link, landmarks, navigation, and footer. `FrameworkLayout.astro` wraps it for collection-backed pages.
- `src/components/`: `Nav`, `Footer`, and the schema.org JSON-LD components (Organization, Person, BreadcrumbList).
- `public/llms.txt` is generated by `scripts/generate-llms-txt.mjs` as part of every build. `public/robots.txt` allows GPTBot, ClaudeBot, and PerplexityBot. The sitemap comes from `@astrojs/sitemap`.
- `docs/governance/`: the governance documents, including the Visual Doctrine.

## Forms and workflows

The site links to forms hosted on Tally and embeds the contact form at `/contact`. The Invisible Fragility Index automation (Tally, Make, Google) lives outside this repository and is not modified by it. No form identifiers other than public form URLs appear in the source, and no secrets belong here.

## How to run it

```
npm install
npm run verify-links    # reference integrity and the Editorial Gravity report
npm run verify-routes   # builds, then checks every href against real routes and public files
npm run dev             # local dev server
npm run build           # generates llms.txt, then static build to dist/
```

## How to extend it

1. Write a new `.md` file in an existing collection, or a new collection following the same pattern in `config.ts`.
2. Fill in the frontmatter honestly. The schema checks type, not truth.
3. Add real links to other pages in the body, and declare them in `references`.
4. Run both verification scripts. Fix the actual problem; never silence the check.

Writing rules live in `CLAUDE.md`. Colors, links, and the waveform follow `docs/governance/visual-doctrine.md`.

## What this does not do yet

No glossary, research section, blog, or site search. No analytics. Military and Sovereign applications are deliberately excluded until their gates open.
